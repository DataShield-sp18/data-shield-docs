## What this repo is

A Docusaurus 3 site containing the full project documentation for **Data Shield**, a
local-first PII/PHI de-identification product. This repo is documentation content only —
there is no application source code here. All content lives under `docs/` as Markdown.

This is one of three separate documentation systems for the Data Shield project, each with
a distinct audience — do not blur them:

- **This repo (`data-shield-docs`)** — full project documentation: architecture, engineering
  internals, ML model, ops reference, compliance. Audience: leadership/stakeholders and
  anyone who wants the full picture without cloning the app repo.
- **`../data-shield/.wiki/`** (sibling repo, Obsidian vault) — the engineering/agent source
  of truth, with file:line-level detail. This site links out to it rather than duplicating
  it; when a wiki fact changes, update the link/pointer here, not a copied paragraph.
- **`../data-shield/user_docs/`** (sibling repo, also Docusaurus) — the end-user manual for
  people using the running app. Different theme (blue, `#2563eb`) — this site deliberately
  uses a distinct warm charcoal/amber palette (see `src/css/custom.css`) so the two are never
  confused from a screenshot alone.

`BUILD_PROMPT.md` is the original brief this site was built from — it documents sourcing
rules (only assert what traces back to real repo/wiki content, never invent metrics,
timelines, stakeholder names, or approvers) and the intended `docs/decisions/` decision-log
section. That section has not been built yet (see `docs/intro.md`'s closing note — it's
"planned but not built," pending format sign-off from the engineering lead); `sidebars.js`
has no `decisions` category. Don't add one speculatively.

## Commands

```bash
npm install       # install deps
npm start         # local dev server with live reload
npm run build     # production build into build/ — run this before considering doc changes done
npm run serve     # serve the production build locally
npm run clear     # clear the .docusaurus cache (fixes most stale-build weirdness)
npm run deploy    # publish to GitHub Pages
```

There are no tests and no linter configured — `npm run build` is the correctness check
(Docusaurus is configured with `onBrokenLinks: 'throw'`, so a bad internal link fails the
build rather than warning).

## Content architecture

- `docs/` mirrors `sidebars.js` exactly, one category per top-level folder: `product/`,
  `architecture/`, `engineering/`, `features/`, `ml/`, `operations/`, `compliance/`, plus
  root-level `intro.md`. When adding a page, add it to `sidebars.js` too — nothing appears
  in the sidebar automatically.
- `docusaurus.config.js` uses `routeBasePath: '/'` (docs are the whole site, no separate
  `/docs` prefix) and `@docusaurus/theme-mermaid` is enabled — diagrams use fenced
  ` ```mermaid ` blocks directly in Markdown.
- `product/stakeholders.md` is a deliberate `TODO` scaffold — real stakeholder names and
  approvers were never provided. Leave rows as `TODO`/em-dash rather than inventing names;
  same rule applies to any `Approver` field that shows up elsewhere.
- Style rules that apply to every page here (from `BUILD_PROMPT.md`, still in force):
  no file:line references (link to the `.wiki/` page instead — this site is for readers who
  won't open the codebase), no invented metrics/timelines/costs, no emojis, plain Markdown
  (MDX only where Mermaid requires it).
- `build/` and `.docusaurus/` are generated output — don't hand-edit files there; they're
  regenerated by `npm run build` / `npm start` and are gitignored except `build/` isn't
  (check `git status` before assuming a `build/` change is safe to discard).

## Hosting

Deployed to GitHub Pages, public repo, `static/robots.txt` disallows all indexing. This is
unlisted-URL protection only, not real access control — a deliberate known tradeoff for this
POC stage (see `docs/architecture/security.md`). Because the repo is public, nothing should
be added here that wouldn't be fine as a URL someone stumbles onto.
